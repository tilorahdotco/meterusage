# Windows

Part of [project knowledge](../KB.md). Windows paths, file trust, CLI discovery, packaging, tests, updater and CI.

- ADR 0038 resumes Windows with the `windows-latest` CI runner as the only test machine; there is no physical Windows PC. The former RN/Tauri Windows-first plan stays superseded.

- Windows app data is `%APPDATA%\MeterUsage`. `%APPDATA%` is used only when it lies inside the user profile; otherwise MeterUsage uses `%USERPROFILE%\AppData\Roaming`. Installed Windows preferences use `preferences.json` through the demo/test JSON writer; an unparsable file is renamed `preferences.json.damaged-<time>`. `src/main/platform.ts` holds these seams, and each helper takes the platform explicitly so Linux tests cover Windows branches.

- Windows file trust: POSIX owner and mode checks are skipped because Windows `stat` has no owner and synthesizes mode bits; profile ACLs are the boundary. Symlink, file type, nlink, size and change-during-read checks remain. The API billing reader `lstat`s before opening because Windows has no `O_NOFOLLOW`.

- Windows CLI discovery searches folder by folder (npm global folder, `.cargo/bin`, `.bun/bin` for OpenCode, `.local/bin`, then unquoted `PATH` entries split on `;`), preferring `.exe` over `.cmd`/`.bat` within a folder. Spawned binaries and searched folders must be drive-letter or UNC paths; `/bin/ps` would otherwise resolve to `C:\bin\ps.exe`. Shims run through fixed `%SystemRoot%\System32\cmd.exe /d /s /c` only when no argument contains `"`, `%`, `!`, `^`, a line break or a trailing backslash. Spawns set `windowsHide`; timeouts end the process tree with `taskkill /t /f`. If `taskkill` fails, the direct child is killed and its pipes released so the request settles. Connected Codex passes quoted keyring configuration, so it cannot run through an npm shim until the desktop-connection stage handles it.

- ADR 0040 Windows desktop connections: `src/main/providers/windows-dpapi.ts` unwraps `Local State` `os_crypt.encrypted_key` (`DPAPI` prefix) with a fixed PowerShell `ProtectedData.Unprotect` call (wrapped blob in the child's `METERUSAGE_DPAPI_INPUT` environment variable, key on stdout; the first Windows run showed `powershell.exe -Command` does not reliably pass redirected stdin to the script) and decrypts `v10` AES-256-GCM values; `v20` is refused. Claude reads `%APPDATA%\Claude` cookie stores with `node:sqlite` `immutable=1&mode=ro` and reports a fixed "quit Claude Desktop" stage when a store cannot be opened. Grok Bot reads `%APPDATA%\Grok Bot`. Antigravity discovery uses one fixed CIM + `Get-NetTCPConnection` script (no double quotes, which PowerShell 5.1 can strip) and a 60-second Windows bound. npm `.cmd` shims resolve to `node.exe` + script (`npmShimTarget`), so connected Codex works without `cmd.exe`. Saved legacy Grok-via-Cursor sources and API billing **Use saved key** stay macOS-only. Readers take explicit app-data roots so Linux tests exercise them; `tests/windows-connections.test.ts` covers them, and Windows-only tests in `tests/platform.test.ts` run a real DPAPI round trip and a full Claude Connect.

- Windows `atomicJSON` retries an `EPERM`/`EACCES`/`EBUSY` rename up to five times and removes its temporary file on failure. Preferences treat only unparsable content as damage, not a locked read.

- Windows copies process environments with their original casing (`Path`). Use `envValue`/`withEnvValue` rather than `env.PATH` for anything that can run on Windows.

- Windows shell: colored notification-area icon with a usage tooltip (no text tray image), taskbar-anchored flyout, tray click toggles despite blur, **Copy card image** instead of the share sheet, no default menu bar, AppUserModelID `dev.meterusage.app`. Renderer copy says "this PC" when `state.platform` is `win32`.

- Windows releases are built by the manual `Windows release build` workflow (`.github/workflows/windows-release.yml`, inputs `version` and `build`). It runs `test:windows`, packages with `-c.extraMetadata.version`/`-c.buildVersion`, runs both smoke scripts and uploads `windows-release-assets` (installer, zip, `SHA256SUMS`). It runs only from `main`, records the built commit in the job summary and `windows-release-smoke/source-commit.txt`, and never tags or publishes. For a Windows-only release, publish by hand with `gh release create v<version> --prerelease --latest=false --target <that full SHA>` and those three files; GitHub's asset digests feed the Windows updater. If the release also carries macOS assets, use `gh release upload` and merge both platforms' lines into one LF `SHA256SUMS`.

- Windows packaging: `pnpm package:win` builds unsigned NSIS and zip x64 artifacts named `MeterUsage-<version>-win-x64.<ext>`. `after-pack.cjs` leaves `MeterUsage.exe` unchanged; the macOS Keychain helper is a mac-only extra resource. A Windows GUI-subsystem exe prints `json` output only when stdout is redirected (for example `MeterUsage.exe json > report.json`); JSON mode exits after the write callback so pipes flush.

- `pnpm test:windows` runs every test file except ten: those whose fixtures need POSIX modes, symlinks, shebang scripts or Electron singleton symlinks, and the macOS updater tests (ditto/codesign staging). `tests/windows-updater.test.ts` covers the Windows updater on every platform.

- Windows updater (ADR 0039): selects `MeterUsage-<version>-win-x64.exe` under the `releaseOwners` list, verifies the GitHub digest plus PE/NSIS structure (no signature), installs only when `Uninstall MeterUsage.exe` sits beside `MeterUsage.exe`, and starts the staged installer with `/S --updated --force-run` from the end of quit (`launchPendingInstaller`). The CI install smoke (`windows-install-smoke.ps1`) checks silent install, relaunch by `/S --updated --force-run` after the app is force-stopped, and silent uninstall; it does not exercise the in-app spawn at quit. Installed copies remove stale `MeterUsageUpdate-*` temp folders at launch. Portable copies never auto-install and answer Install with a fixed download message. New test files run on Windows by default. The Windows job checks out with `core.autocrlf false` so LF fixture hashes match.

- The CI `windows` job runs typecheck, `pnpm test:windows`, an informational full suite, the build, packaging and `Scripts/electron/windows-smoke.ps1` (headless JSON with demo and real empty profiles, a demo GUI first launch and relaunch with window-count checks and screenshots). Artifacts: `windows-smoke` and `windows-packages`.
